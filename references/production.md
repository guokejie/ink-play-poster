# 局部控制与标题分层

## 参考选择
读取 detail-index.json；每条含稳定ID、原图、归一化裁切框、控制维度与禁止迁移项。局部图片来自原九张海报，未借用外部项目视觉资产。整图控制总体语法，局部图控制一个明确轴，不能把局部图的角色、品牌、器物当新主题。

`python scripts/reference_sheet.py --style P08 --axis title --out work/P08-title.png`

也可不传out，只返回检索结果。轴为title/line/mass/accent；无匹配时明确失败，不自动借其他风格。生成模型参考板无编号、说明标签或系统字体目标字；索引说明保存在旁边JSON，避免标签进入成图。裁切图仍含原图内容，提示词必须明确“只借笔触/比例，不借原文字”。

语义文字→字形骨架→笔触→版面分别控制。例如P08可用不均匀大写节奏启发中文胖字，但不可强制照搬拉丁字形。中文优先可读性。P05宽字距与P09连笔是不同策略，不统一成一种胖字。

## 标题执行分支
短文案允许一体生成；是否分层由精度、修复和图文关系决定，不按文字长短决定设计完成度。用户强调字体还原、只改标题或一体生成不稳定时，使用：
1. 生成无字底图，按新版构图预留标题区并检查无伪字。
2. 查看选中风格title局部参考，生成**只有目标文字**的独立标题层；目标原文只放提示词，不在参考板上先用标准字体写一遍。不要复制原字或品牌。
3. 放大逐字核对标题层，确认笔触和字形，再合成。字形错误先修标题层，底图锁定；无法生成正确标题则用已确认支持中文的本地字体准确排字，并披露字体还原限制。
4. 使用命令：

`python scripts/compose_title.py --base base.png --title title.png --out final.png --x 8% --y 7% --width 84%`

依赖`python -m pip install -r requirements.txt`，仅在当前环境缺Pillow且确需此工具时安装。输入图片保持原样；输出只支持PNG，附 `.layers.json` 记录位置、源文件与阈值。保留底图、标题原层和清单即可重新调整，清单内路径是当前创作项目记录，不能作为Skill内置样例发布。

工具只提取黑墨：白底转换为透明，灰度连续映射保留抗锯齿，原透明度参与计算。--white默认245，--black默认40；白底残影可下调white，细淡笔丢失可调整范围。彩色字不适用，需另用透明彩色层。越界或空标题报错，不静默裁字，不覆盖输入。工具不能验证文字正确性，最终仍需打开成图。

## 参考职责与修改锁
brief可增加 `reference_roles`，记录每个输入是subject/style/title/previous-result，以及控制轴和锁定项；用户原文永远来自exact_text。两种风格时 `aux_axes` 必须显式填写，如 `["palette"]`，blend说明“只借少量绿”。脚本仅注入辅风格指定字段，局部图也仅选相应轴。

局部修改先保存新版本，再锁定主体形状、位置和未修改区域；仅换标题时复用相同base。用差分检查底图是否变化，并目视检查字的边缘、排列和信息层级。不是每张海报都强制分层，也不增加新的用户确认步骤。

## 首轮实测发现
P08细线单品容易变成规整示意图；要求曲线、书页/器物结构轻微不平行和不对称，而不是只给光滑线条加噪点。P08标题可能偏平滑，应检查字形与原图的节奏，中文偏旁完整性优先。不同风格对照不能只靠换主体成立。

空间设计先按composition.md决定，底图不得自动预留上部大矩形。复杂遮挡需明确前后图层或通过图像编辑实现；compose_title.py不自动处理物体遮挡标题。

## 三层标题控制与独立制作 v8

当用户强调字体风格还原，或已经反馈“普通、呆板、像标准字体”时，优先制作独立标题；不再次默认一体生成。普通探索仍可一体出草稿。若具体构图需标题与主体复杂穿插，先规划遮挡层；简单白底叠合不能自动处理交错。

1. 从typography.md选定字体语言并实际查看原局部；在type_plan.glyph/stroke_logic/rhythm中写出“看到了什么→本案哪些字怎样转译”。语义文字、单字骨架、笔画形态、整组排布分别控制。不要用“手写随性”等概括替代具体决定。
2. 用自己的选定参考制作三层控制板：

   `python scripts/title_reference.py --style P04 --out work/P04-title-control.png`

   顶部为整组标题，左下为单字或字形片段，右下为局部笔段；旁边JSON记录来源和职责。P07现有title裁切是窄长正文，选择几何刊头时必须补看全图，不能误当同一种字。板中均是拉丁参考，不能声称提供目标中文的字形答案。不同文字长度由本案设计排布，不自动套四字双竖列。
3. 先锁定无字插画底图，或复用已满意的底图，再单独生成目标标题。模型输入参考板只控制形态；准确目标文字只写进提示词，不先用系统字体把目标字印在参考板上。不把外部项目的品牌或裁切加入本库。
4. 标题提示词必须包含：exact_text、明确读序、各字骨架与部件比例、参考中的笔画特征、整组形状及字号关系。只生成目标黑墨标题，不出现参考原词、说明标签或新口号。不得把所有参考统一改成畸形儿童字；P02/P07保留需要的规整对比，P09保留流畅性。
5. 放大核对中文部件及笔画，再缩略核对词团与整图；并列写出参考特征“已出现/缺失”。文字错误不放行，形态缺失也不能用纹理或整体配重抵消。锁定底图，仅重做最严重的标题问题，最多两轮同类修复后报告限制或换手写标题来源。
6. 使用现有compose_title.py提取墨色和合成，保留标题原图、底图和.layers.json。采用普通本地字体只保证准确排字时，明确标为字体还原受限，不声明手写风格通过。

这个流程借鉴了heytea-style对语义、骨架、笔画、排布的分离控制（https://github.com/Hchen1218/heytea-style/blob/main/references/lettering-guide.md）；本库继续使用自己的九图参考，不引入其品牌素材或限定的幼拙审美。
